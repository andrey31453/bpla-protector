# Визуализация ЗОК на подстанции — принятый кадр

`zok-sub-c1.jpg` — вид изнутри контура ЗОК на подстанции 110/35 кВ: полотно над двором, стена
на заднем плане, фланги с мачтами, оттяжками и бетонными анкерами. Контур заканчивается на
дальней границе ОРУ (Z = 100 м): защищается станция, а опора ВЛ и линия за ней остаются вне
контура. Текущий итог папки, всё остальное (другие ракурсы и ранние черновики) по решению
заказчика удалено.

Исходный снимок подстанции, поверх которого собран кадр, в репозитории не хранится: по
решению заказчика файл удалён (права на фото и на сам объект не подтверждены). Для
пересборки нужна копия снимка — путь к ней задаётся переменной `ZOK_SRC`, см. «Как
воспроизвести».

Полотно поверх фото не «наклеено»: ЗОК нарисован в метрах и спроецирован той же камерой, что
снимала объект, поэтому ячейка, пояса и мачты уходят по перспективе, а дальние части уходят в
воздушную дымку.

## Как задана сцена

| Параметр | Значение | Откуда взято |
| --- | --- | --- |
| Линия горизонта | 162 px | дальний край поля в кадре |
| Фокус | 600 px при ширине 800 px (≈65° по горизонтали) | согласуется с обычной камерой; проверка по глубине: ближнее здание ≈34 м, задняя граница двора ≈100 м |
| Высота камеры | 17,3 м над землёй | по пилону ВЛ в кадре (≈40 м при базе на Z ≈120 м) и по высоте ближнего здания (≈6 м) |
| Направление света | спереди-слева, высота ≈45° | по освещённым граням ближней техники |
| Контур ЗОК | по границам площадки: X от −29 до +37 м, вглубь — за камеру, задняя граница Z = 100 м | забор площадки в кадре стоит на X ≈ −29 и X ≈ +37; Z = 100 м — передний ряд дальних ячеек ОРУ |
| Почему граница на 100 м | за контуром остаётся дальний ряд оборудования и опора ВЛ: её точка опоры на земле — строка ≈248 px, это Z ≈120 м | по фото: защищается только станция, линия за пилоном — нет |
| Высота полотна | 26 м | выше всего оборудования и вводов |
| Мачты | 8 решётчатых стоек 26 м: фланги Z = 63 и 100 м, задняя стена X = −12 и +12 м; шаг по X 17–25 м, по Z 37–38 м; у каждой бетонный башмак, у контурных — оттяжки к анкерам за контуром | по фото-референсу ЗОК |
| Полотно | канатная сетка; ячейка в картинке 0,7 м | по ТЗ силовой слой 250–500 мм; в кадре ячейку пришлось увеличить — на 60–120 м настоящая нить не видна |
| Нити против пелены | нити рисуются там, где ячейка в кадре ещё разрешима (чётко до ≈52 м, гаснут к ≈92 м); дальше полотно читается пеленой, а структуру держат мачты и канаты | иначе на 100 м получается частокол нитей, сходящихся в точку сходу: его читают как канаты, уходящие вдаль по линии |
| Опорные канаты кровли | по линиям мачт вдоль и поперёк + замкнутый периметральный канат по кромке кровли | по схеме каркаса: это те канаты, на которых висит полотно, они же показывают кромку защиты |
| Пояса-канаты | 4 уровня через 5,5 м, провис 0,22 м | по рендерам и фото конструкций |
| Тень полотна | на траве, по солнцу спереди-слева | расчёт проекции кровли на землю |

## Как воспроизвести

Нужны `numpy` и `Pillow`. Исходный снимок в репозитории не хранится, поэтому путь к его
копии задаётся переменной `ZOK_SRC`; кадр ложится в эту же папку (переопределяется `ZOK_OUT`):

```
ZOK_SRC=/путь/к/snimok-podstancii.jpg python3 docs/images/zok-viz/tools/family_c.py c1
```

Проверено: из копии снимка (`sha256 f48e7b00cc32…`) скрипт собирает файл, побитово
совпадающий с `zok-sub-c1.jpg` (`sha256 a8232ede0db1…`) — кадр воспроизводится, хотя фото
в репозитории нет. Без `ZOK_SRC` и без фото по старому пути скрипт останавливается с
сообщением, а не подставляет другое изображение.

Тем же скриптом собираются и другие ракурсы, если понадобятся: `c2` — контур над двором,
кадр через фронтальную стену полотна; `c2l` — то же с более тонким полотном; `c1d` — плотное
полотно и крупные пояса. В папке они не хранятся.

## Что измерено

Проверки посчитаны по самому файлу, а не «на глаз». Зоны заданы в координатах исходного кадра
800×531 как (x0, y0, x1, y1); контраст — среднее квадратичное отклонение яркости в зоне;
базовое значение — то же место исходного фото.

| Зона (координаты) | Фото: яркость / контраст | Кадр: яркость / контраст |
| --- | --- | --- |
| Небо под полотном (640, 6, 780, 34) | 254,4 / 0,8 | 230,4 / 22,1 |
| Ближняя техника, не перекрыта (230, 300, 400, 420) | 151,7 / 70,3 | 151,4 / 73,3 |
| Дальний ряд двора (380, 215, 560, 246) | 129,2 / 50,3 | 128,8 / 50,4 |
| Поле за кромкой контура (250, 150, 330, 176) | 192,7 / 54,8 | 176,8 / 52,1 |
| Ствол пилона ВЛ (384, 108, 402, 170) | 177,4 / 63,8 | 170,6 / 62,1 |

Как это читать: ближняя техника не перекрыта и не размыта — полотно идёт над ней; дальний ряд
двора виден через стену полотна почти без потерь (50,3 → 50,4); небо под полотном темнеет на
9 % и получает контраст 22 — это нити над головой; контраст пилона ВЛ сохранён на 97 %
(63,8 → 62,1), то есть за кромкой контура сцена не замылена.

Отдельно проверено численно, что вотермарка исходного фото в правом нижнем углу затёрта травой:
в этом углу контраст 27,3 против 43,0 у фото, логотипа нет.

## Ограничения и честные оговорки

- Защищается только станция: контур заканчивается на Z = 100 м, за ним остаются дальний ряд
  оборудования и опора ВЛ (≈40 м, база на Z ≈120 м). Пилон и провода в контур не входят —
  в реальном проекте ввод ВЛ оформляют проёмом с окантовкой, в кадре проём не показан.
- Дальняя часть полотна (стена на 100 м, а по кровле — дальше 52 м) показана пеленой, а не
  нитями: ячейка 0,7 м на 100 м физически меньше пикселя. Часто нарисованная сетка в этом
  месте читается как канаты, уходящие вдаль, поэтому здесь выбран честный вариант — границу
  держат мачты, пояса и периметральный канат.
- Ячейка полотна в кадре увеличена против реальных 100–500 мм: иначе на 60–120 м нить
  физически меньше пикселя и полотна не видно. Это визуализация, а не рабочий чертёж.
- Геометрия площадки (X −29…+37 м, границы двора, глубины) оценена по фотографии, а не по
  проекту объекта. Перед публикацией числа нужно сверить с документацией заказчика.
- Тень полотна нарисована только на траве: тени на кровлях и на металле оборудования
  не моделируются, для этого нужна 3D-модель техники.
- Люди, знаки маркировки высотных препятствий и молниезащита в кадре не показаны.
- Права на исходное фото не подтверждены: снимок прислал заказчик в переписке. До публикации
  на сайте нужно подтверждение прав, иначе кадр годится только для внутреннего просмотра.
  Это же касается и того, наш ли это объект на снимке.
- Файл отдан в JPEG 1600×1062 без веб-оптимизации. При подключении к сайту нужны копии под
  нужные размеры (AVIF/WebP + JPEG-фолбэк), как для остальных изображений.
- Ранние подходы (ретушь чужого фото и «оживление» рендера заказчика) удалены вместе с их
  контактными листами: подходы закрыты, в папке остался один принятый кадр.
