# Переносимая форма через PHP mail()

**Для переноса скопировать всю эту папку. Другой ИИ начинает с AGENTS.md.**
Используется обычный `mail()`: PHP передаёт письмо локальному sendmail-совместимому
транспорту. В комплекте нет SMTP-логина, пароля, внешнего почтового API и библиотек.

## Состав

```text
mail-form/
  AGENTS.md                 памятка для ИИ и контекст решений
  README.md                 подключение, сервер, проверка
  build.mjs                 автономная сборка или интеграция с Vite
  config/form.json          получатель, поля, сообщения
  config/site.example.json  пример минимальных входных данных сайта
  server/lead.php           обработчик POST
  client/form.mjs           JS-улучшение существующей HTML-формы
  deploy/setup.sh           Debian/Ubuntu: PHP-FPM + локальный Postfix
  deploy/lead-pool.conf     пул PHP-FPM
  deploy/nginx.conf         правила исполнения и закрытия конфигурации
  tests/test_lead.py        PHP-интеграция через фиктивный sendmail
  tests/form.test.mjs       статусы и повторы запросов в JS
```

## Подключение в другой проект

1. Скопировать папку, не переносить чужой дизайн/контент.
2. В `config/form.json` проверить `mail.recipient`, `mail.senderLocalPart`, тему,
   `endpoint` и `returnUrl`. Сейчас получатель временный для проверки владельцем.
   Поля получателя не брать из POST. Публичные контакты сайта менять не нужно.
3. Передать сборщику JSON целевого сайта с `brand` и `baseUrl` (см. пример).
   На выходе требуются `api/lead.php` и `api/lead-config.php`.
4. Подключить статическую разметку формы и JS по контракту ниже.
5. Подготовить сервер, nginx и проверить настоящую доставку.

Сборка без Vite (после основной сборки, иначе она может удалить файлы):

```sh
node mail-form/build.mjs src/data/site.json dist
```

Интеграция в Vite/Nunjucks, используемая сайтом 13:

```js
import { loadForm, mailAssets } from './mail-form/build.mjs'
// При загрузке данных для Nunjucks:
data.form = loadForm()
// В generateBundle плагина Vite:
for (const asset of mailAssets(data.site, data.form)) {
  this.emitFile({ type: 'asset', ...asset })
}
```

Поля/статусы генерировать из того же `loadForm()`, не поддерживать вторую копию JSON.
Исходная папка не должна быть в public/. base64 в конфигурации — не защита секретов.
На GitHub Pages файлы PHP могут скачиваться как текст; никаких паролей внутри нет,
но PHP-отправка там невозможна. Работает только на сервере с PHP.

## Контракт HTML и JS

Существующая форма должна иметь `method="post"`, `action` из `endpoint`, `data-form`.
Поля: `name`, `phone` (обязательные), `comment` (необязательное), скрытое поле
раздела с именем из `hidden.name`, пустой скрытый honeypot `website`.
Ограничения PHP: имя 300 байт, телефон 100, комментарий 8000, раздел 500;
телефон — 10–15 цифр и только символы `+`, пробел, скобки, дефис, цифры.
Форма без JS делает обычный POST и получает HTML-страницу результата.

Узел статуса: `data-form-status`, `role="status"`, `aria-live="polite"`,
атрибуты `data-form-error`, `data-form-send-error`, `data-form-loading`
с текстами из JSON. Статусы переключаются классами `is-visible`, `is-error`,
кнопка блокируется на время запроса, форма получает `aria-busy`.
Оформление этих состояний — задача дизайна целевого проекта; комплект не навязывает CSS.

```js
import { initForm } from './mail-form/client/form.mjs'
// После появления статической формы в DOM, в try/catch реестра проекта:
initForm()
```

JS не рисует контент/ссылки. При ошибке данные не очищаются, при успехе — очищаются.
POST с `Accept: application/json` возвращает `{ "ok": true/false, "message": "…" }`.
Коды: 200 принятие MTA, 405 метод, 413 размер, 422 поля/ловушка,
403 чужой Origin при его наличии, 429 лимит, 503 ошибка транспорта/конфигурации.
Это базовая защита, не полноценный антибот. Origin без заголовка допустим для
совместимости; это не аутентификация. Лимит — минута между попытками с IP,
хешированные файлы в temp (нужна штатная очистка); reverse proxy требует trusted real IP.

## Голый сервер: обычный mail() без внешнего SMTP

PHP 8.1+, PHP-FPM, nginx и локальный Postfix. Сначала проверить ОС, версии,
существующие службы, бэкапы конфигураций. Скрипт — только Debian/Ubuntu с systemd.
На сервере с уже работающей почтой не запускать без аудита.

```sh
# На сервере от root; домен заменить на домен целевого проекта:
MAIL_DOMAIN=example.org bash mail-form/deploy/setup.sh
```

Скрипт устанавливает пакеты, пул `/run/php/site-lead.sock` и Postfix с прямой
доставкой на MX получателя. При обнаружении существующего MTA останавливается.
Postfix принимает только локальные подключения: внешний входящий SMTP не нужен.
Скрипт не меняет DNS, не настраивает DKIM, не отправляет тестовые письма,
не применяет nginx и не публикует сайт. Обновления пакетов и новые службы
влияют на сервер: запускать только осознанно с разрешения владельца.

Для nginx скопировать `deploy/nginx.conf` в `/etc/nginx/snippets/site-lead.conf`
и включить `include /etc/nginx/snippets/site-lead.conf;` внутри нужного `server {}`.
Его root должен указывать на папку с созданным `api/`. При другом расположении
или нескольких сайтах на одном сервере адаптировать имена пулов/сокетов и пути.
Проверить `nginx -t`, затем reload. Другие PHP-файлы должны отвечать 404,
а `lead.php` — исполняться, никогда не скачиваться исходником.

Прямая доставка требует доступного **исходящего TCP/25**. Если провайдер его
блокирует — запросить разблокировку, не маскировать ошибку успешным статусом.
Для Gmail важны репутация IP, A/PTR/имя mail.<домен>, SPF; DKIM/DMARC повышают
достоверность отправителя. Успех mail() не доказывает доставку: Postfix может
оставить сообщение в очереди или получить отказ Gmail. Не создавать вторую
SPF-запись поверх существующей; изменения DNS сначала согласовать с владельцем.

Диагностика: `postqueue -p`, `journalctl -u postfix`, почтовые логи ОС,
`systemctl status php<версия>-fpm`, `nginx -t`. Убедиться в envelope sender;
если системный MTA подставляет www-data, настроить его преобразование на сервере.
Не подставлять пользовательские значения в заголовки/аргументы sendmail.

## Тесты без настоящих писем

Из корня проекта (нужны Node, PHP CLI 8.1+, Python 3):

```sh
node --test mail-form/tests/form.test.mjs
python3 mail-form/tests/test_lead.py
# Проверить именно собранный сайт:
python3 mail-form/tests/test_lead.py dist/api
```

Первый PHP-тест автономен: сборка во временную папку из example-конфига.
В обоих режимах sendmail подменяется локальной заглушкой. Проверяются валидация,
лимит, honeypot, Origin, размер, UTF-8 письмо, ошибка mail() и ответ без JS.
После разрешённой выкладки отдельно проверить заявку и входящие/спам получателя.
