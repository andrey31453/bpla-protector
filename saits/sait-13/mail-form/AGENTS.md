# Продолжение работы: RuSender

Сначала прочитай README рядом. Эта папка переносима целиком, без зависимостей
от соседних сайтов. Не переноси бренд, отправителя и получателя автоматически.

Владелец заменил прежний PHP mail()/Postfix на RuSender HTTPS API.
Для сайта 13 from только info@zok.pro; актуальный recipient — в config/form.json.
Факты/поля/адреса — config/form.json, бренд и домен — входные данные сборки.
build.mjs создаёт два PHP-файла, клиентский модуль ничего не рендерит.

Токен НИКОГДА не хранить в этой папке/репозитории/сборке/браузере.
Источник при деплое — GitHub Secret RUSENDER_API_TOKEN, на сервере —
/etc/site-lead/rusender-token. Опубликованный в переписке токен рекомендуется
отозвать и заменить. Не повторяй его в ответах и логах.

setup.sh готовит только PHP-FPM/cURL и собственный пул, Postfix не трогает.
Внешний SMTP и mail() не использовать как fallback. Старые настройки SPF/PTR
для прямой доставки веб-сервером не являются инструкцией подключения RuSender.

Сохраняй проверки/лимит/honeypot и серверный выбор адресов. HTTP 202 с data.id
означает принятие провайдером, не доставку. Idempotency-Key стабилен при одном
внутреннем сетевом повторе, новый POST — новая операция. См. ограничения README.
Тесты не должны обращаться к настоящему API или отправлять письма.

Интеграция сайта 13: nunjucks-plugin.mjs, src/partials/form.njk,
src/js/modules/form.js; nginx-фрагмент ставит deploy/install-tls.sh.
Секрет и установка сервера — только по разрешению владельца, публикация по
правилам репозитория. Не утверждай доставку без проверки RuSender/получателя.
